## 6. Remaining Security Blockers

1. **`xlsx@0.18.5` Replacement Options:**
   - `read-excel-file` (MIT, zero known direct CVEs) and `exceljs` (MIT, recent CVE-2026-78207/78208 in `<=4.4.0`) do **not** support legacy binary `.xls` files.
   - SheetJS `>=0.20.2` fixes `CVE-2023-30533` and `CVE-2024-22363`, but is no longer published on npm and uses SheetJS's custom CDN distribution (license review required).
   - **Recommended Path:** Keep `.xls` untouched in the legacy desktop UI for now; in Phase 2 web importer, support `.xlsx` via `read-excel-file` + `.csv` and show an explicit message if a user uploads `.xls` ("Please save `.xls` as `.xlsx` or `.csv`"), or obtain explicit user sign-off to drop `.xls` in Electron too.
2. **Workers Free `10 ms` CPU Benchmark for `PBKDF2`:** Must be benchmarked on a live Worker isolate before enabling production password logins.
3. **Email Verification & Password Reset Architecture:** Requires choosing a transactional email provider (or OAuth2-first authentication) plus adding `verification_tokens` to D1.
